## Result

**Pass.** Release 1, built from committed content with the real model, retrieves the same records as
today's ChromaDB collections, with the same scores and the same verdicts.

| Check (spec §7.3 step 4) | Compared | Failing |
|---|---|---|
| Record IDs and texts (text hash per record) | 293 | 0 |
| Stored vectors, cosine ≥ 0.9999 with ChromaDB's | 293 | 0 |
| Gold-query verdicts identical to the legacy scripts' | 74 | 0 |
| Gold-query top-k IDs, order, similarities within 0.001 | 74 | 0 |
| `retrieve()` runs: each gold query unscoped and scoped (148), plus 12 multi-query, multi-service cases | 160 | 0 |
| Order swaps between near-equal results (tie swaps) | — | 0 |

Vector agreement, measured directly against the committed baseline vectors:
- lowest cosine over all 293 records: **1.000000000** (9 decimals);
- largest single-component difference between the normalised vectors: 1.03e-6.

ChromaDB stored the e-Return and BDRIS vectors unnormalised, so the vectors were normalised before
the component comparison.

The machine-readable report is `docs/reports/m1-parity/release1_parity.json`, the output of
`gsn parity --release 1`, exit 0.
