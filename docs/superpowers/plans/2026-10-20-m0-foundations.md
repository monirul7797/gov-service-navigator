# M0 Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An empty but real five-service stack (caddy, web, engine, worker, postgres) that runs with
one command on the owner's PC and in CI, with the database role model, an append-only audit log,
skeleton frontends and a green CI pipeline. No product features.

**Architecture:** Monorepo next to the untouched legacy code: `web/` (Rust, axum), `engine/`
(Python package `gsn`, used by both the engine and worker containers), `frontend/public/` and
`frontend/admin/` (SvelteKit static builds bundled into the web image), `contracts/` (language-
neutral JSON examples), `db/` (init script + SQL migrations), `deploy/` (Caddyfile, helper scripts).
Docker Compose wires them; GitHub Actions runs every gate.

**Tech Stack:** Rust stable (edition 2024) + axum 0.8, tokio, sqlx 0.8 (postgres, migrate),
reqwest 0.12 (rustls), tower-http 0.6, tracing (JSON); Python 3.12.10 + FastAPI, uvicorn,
psycopg 3, pytest; SvelteKit + Svelte 5 + TypeScript + Tailwind CSS 4 + adapter-static, Vitest,
ESLint; PostgreSQL 17 + pgvector; Caddy 2; Docker Compose; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-20-system-architecture-design.md` (M0 row of §11; also
§3, §6.1 roles, §7.1, §8.2–8.6, §8.9, §10).

- Work on branch `feat/m0-foundations` in the main checkout. `acquisition/*` holds the owner's
  uncommitted edits: never touch, stage or discard them.
- Local machine (updated 2026-10-21): Windows; Rust 1.99.1 is installed but there are **no MSVC
  Build Tools**, so Rust is compiled and tested **only inside Docker** via
  `python tools/cargo_docker.py <cargo args>` (Task 3). Docker Desktop 29.9.1 / Compose v5.6.0 lives
  on `G:\Docker`; if `docker` is not found in a shell, prepend `G:\Docker\DockerDesktop\resources\bin`
  to `PATH` (it also holds `docker-credential-desktop`). C: has only ~4 GB free: run npm with

  environment `.venv` at the repo root (gitignored; created in Task 1), never the global Python;
  legacy root scripts such as `test_multiturn.py` keep using the global Python.

  `python test_multiturn.py` must keep passing (set `PYTHONIOENCODING=utf-8` on Windows).
- Long-running services: exactly `caddy`, `web`, `engine`, `worker`, `postgres`. One-shot jobs
  (`migrate`, `itest`) reuse the web/engine images and exit.

  only as `${GSN_ADMIN_PUBLISH:-127.0.0.1:8081}:8081`. Nothing else has `ports:`.

- Svelte 5 in runes mode (`compilerOptions.runes = true`); SvelteKit CSP `mode: 'hash'`, no
  `'unsafe-inline'` in `script-src`. Public app `<html lang="bn">`; admin app `<html lang="en">`.
- Logs: one JSON object per line on stdout.
- Pinned toolchains: Python 3.12.10, Node 24 (`engines.node: ">=24 <25"`), Rust **1.99.1** in
  `rust-toolchain.toml` and the `rust:1.99.1-bookworm` image (verify the tag with `docker pull`;

- Shell scripts, Dockerfiles, `Caddyfile` and SQL use LF line endings.
- Every host-side `python -m pytest …` command in this plan means `.venv/Scripts/python -m pytest …`

## Review Focus

1. **CRLF line endings on Windows** — `db/init/10-roles.sh` checked out with CRLF makes Postgres
   initialisation fail inside Linux. Expected: `.gitattributes` forces LF; a test fails if any
   `*.sh`, `*.sql`, `Dockerfile` or `Caddyfile` in the repo contains `\r\n` (Task 1).
2. **Secrets or bulk data copied into images** — the web build context is the repo root, which
   contains `setenv.bat` (LLM key), `.env`, `data/` and review bundles. Expected: `.dockerignore`
   excludes them; a test asserts the required entries (Task 1).
3. **Passwords with URL-special characters** (`@ / : # % ?`) break URL-style connection strings.
   Expected: connections are built from parts; tests use such a password in Rust and Python
   config (Tasks 2, 3).
4. **Admin listener accidentally public** when `GSN_ADMIN_PUBLISH` is unset or a new service adds
   `ports:`. Expected: a test parses `compose.yaml` and fails on any publication other than the
   two allowed ones (Task 5).
5. **Engine or database down/slow at start** (M2 will load a 2 GB model). Expected: `web` starts
   and serves `/healthz` without the database; `/readyz` reports `503 degraded` instead of
   crashing; engine healthcheck has a 120 s start period (Tasks 3, 5).

  `build_command(repo_root: Path, cargo_args: list[str], image: str) -> list[str]` →
  `["docker", "run", "--rm",
  "--mount", "type=bind,src=<repo_root/web>,dst=/work/web",
  "--mount", "type=bind,src=<repo_root/db>,dst=/work/db,readonly",
  "--mount", "type=bind,src=<repo_root/contracts>,dst=/work/contracts,readonly",
  "-v", "gsn-cargo-registry:/usr/local/cargo/registry", "-v", "gsn-rustup:/usr/local/rustup",
  "-v", "gsn-cargo-target:/work/web/target", "-w", "/work/web", image, "cargo", *cargo_args]`.
  **The repo root is never mounted**: crate build scripts and proc-macros run as root with network
  access, so the container must not see `setenv*.bat`, `.env`, `data/` or `.git/` (hooks). Only
  `web/` (read-write), `db/` and `contracts/` (read-only; `web/` reads `../db/migrations` and
  `../contracts`) are bind-mounted. `--mount type=bind` is used instead of `-v` because it fails
  when a source is missing instead of silently creating an empty directory. Docker parses a
  `--mount` value as one CSV record, so a source path containing a comma or a double quote is
  CSV-quoted (`"src=...,..."`, inner quotes doubled); spaces need nothing and each whole `--mount`
  value stays one argv element. Named volumes keep downloads, components and build output between
  runs on the Docker disk on G:. CLI `python tools/cargo_docker.py <cargo args…>` exits with cargo's exit
  code, and if `docker` is not on PATH it retries with `G:\Docker\DockerDesktop\resources\bin\docker.exe`
  before failing with a clear message. Tests (`.venv` pytest): image name from a toolchain file;
  exact argv for `["test"]`; the bind set is exactly {web rw, db readonly, contracts readonly} and no
  bind source or destination is the repo root; a repo path containing spaces stays one argv element
  per mount and a path with a comma or quote round-trips through a CSV parse; exit code passthrough
  with a fake runner.
